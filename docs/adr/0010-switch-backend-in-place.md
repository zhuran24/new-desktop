# 跨后端换模型在原会话里原地进行

会话可以在 Claude 和 GPT 模型之间切换，Claude 走 Claude Code，GPT 走 Codex（ADR 0009）。跨后端换模型时不开新会话，也不算分叉：在两个回合之间，守护进程把到目前为止的对话转换成另一边的会话格式，在它上面拉起新的后端进程，界面上仍是同一个会话，对话接着往下走。转换方式（research/round7/、research/round9/BRIDGE.md §5）：Claude → Codex 读 New Desktop 钩子 mod 导出的当前有效对话，用 app-server 的 `thread/inject_items` 注入（格式照 Codex 官方导入器；官方导入只能整段导、还丢 Edit 内容和图片，所以不用它）；Codex → Claude 把转换后的条目从 stdin 回放进 Claude 后端进程，由 CLI 自己落盘，不直接写它的记录文件。Claude Code 没有导入 Codex 会话的功能（只能导入配置）。owner 的理由是：正常情况下换模型不会分支。

## Consequences

- 一个会话随时间对应一串后端会话。回退记录和会话树要能跨这几段拼起来。
- 两边模型自己的内部推理（Claude 的签名思考、Codex 的加密推理）带不到对方那边。来回切换只追加对方新增的那段，所以切回来后，各自模型仍能用自己先前的推理（离线已实测，真实 API 是否接受待验证）。
- 以下按「正常情况下换模型会怎样」来定（owner：类似的问题都按正常情况走）：
  - 换模型不影响已经在跑的后台任务：旧后端退役（同 ADR 0008），任务和定时事项转接给新后端会话（ADR 0016），跑完再收掉。当前是 Codex 时，模型用 `nd_tasks` 动态工具操作它们，结果用 `turn/start.toolOutput` 投入，以线程历史里它后面出现模型产出为投完；当前是 Claude 时同 ADR 0008。定时事项留在原 Claude 进程里到点，触发转投。
  - 回合进行中选了新模型，等这一回合结束再切，和 CLI 里改模型从下一轮起生效一样。
  - 权限模式、effort、工作目录等设置照带过去，换成另一边对应的设置；对方没有对应项的，用对方的默认值。
- 「等这一回合结束再切」就是这一回合的 `result` 一到就切。
- 换后端的固定顺序：旧后端先退役，再导出，再写进新后端（research/round10/COMPONENTS.md §7.4）；切换期间到达的用户消息和转投由守护进程代持，切完再投。同步点失效（比如压缩跨过了上次同步的位置）时，在同一段里新建一个同种后端会话，不硬接。
- Codex 一侧退役不需要钩子：0.160 的旧 Codex 线程只会因目标续接、服务端队列，以及同一 app-server 里别的根线程用 v1 原生 `send_input` 唤醒它而自己起回合；子代理完成、子代理发消息、后台终端结束都不会。退役时暂停它的目标，排队消息由发送台代持（不用 Codex 的服务端队列），保持加载和订阅，不等子代理跑完就切；结果从子线程和终端事件转投。它若仍自己起回合（`send_input` 跨根唤醒关不掉），立即中断兜底，这是事后挡；中断不停已派出的子代理和已登记的终端（research/round11/ANSWER.md，步骤见 research/round10/COMPONENTS.md §7.4）。旧线程的原生子代理、后台终端转接给新的 Claude 后端会话，v2 子代理只能看和停。切回这条线程时，它没跑完的代码模式单元照原生接着跑（research/round13/DESIGN.md §4.2、§4.4）。
- 这条依赖 Codex 的两条行为，Codex 升级关卡要回归：子代理完成、子代理发消息、后台终端结束不唤醒空闲的根线程；中断不停已派出的子代理和已登记的终端。Codex 若哪天加上「任务完成就唤醒调用方」，要重审这条。

## Considered Options

- 换后端时开一个新会话（分叉），原会话保留：owner 否决，因为正常换模型不该分支。
- 从 GPT 切回 Claude 时，若旧 Codex 后端会话还有子代理或后台终端在跑，就等它们跑完再切（上一版的例外）：第 11 轮查清子代理和终端本来就不会让旧线程起回合；真正会起回合的目标续接和服务端队列，等子代理跑完也关不掉，所以这条例外没用。
