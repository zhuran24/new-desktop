# 后端用单独下载、单独升级的 Claude Code CLI，不用桌面端带的那份

官方桌面端只留作备份，平常不开；后端用我们自己下载、自己管版本的 CLI，不再受桌面端把 CLI 钉在它自己版本上的限制，也不跟它的更新节奏走。代价是 CLI 的下载、校验、升级和登录续期都要自己管。

## Consequences

- 每个后端进程钉住一组版本组合（CLI、两个 mod、Codex），新版本只给新拉起的进程。
- 退回只改「新拉起的进程用哪一版」的指针；被新版写过的后端会话，先在副本上验证旧版能续接才降级；还被活进程或未验证历史引用的版本不删；上线后监测解码失败、异常退出等，触发退回；真模型回归按改动的影响面做、控制用量（research/round10/COMPONENTS.md §7.9）。
- 新版写的子代理记录、Workflow 运行目录要放进钉在旧版本上的活进程所持有的后端会话时，须在兼容登记里有这一对版本和这类记录；登记由升级关卡在副本上验证后写入。不在登记里时，子代理在记录所在的后端会话里以它的版本续接，Workflow 不续跑（research/round13/DESIGN.md §2.5）。
