# 转接：后台任务留在原进程里跑完，归属跟着当前后端会话走，由守护进程代管

当前后端会话一换（回退、切段、换后端、改启动参数），会话里还在跑的后台任务就转接给新的当前后端会话：新模型用原 id 查看、读输出、停止、给子代理发消息、删定时事项，结果以当前后端的通知格式进它的对话。任务本身不搬，留在原来的持有者（退役进程、Codex 线程、守护进程拉起的子代理进程）里跑完，新模型对它们的操作由守护进程代管、转给持有者。owner 要的是新模型把这些任务「当自己的来用」；stream-json 下又没有不打断就能把在跑任务交给新进程的办法，代管是唯一不中止、不重跑、不丢退出码的做法（research/round13/DESIGN.md §2.9）。

## Consequences

- 归属只有一条规则：会话的全部在跑后台任务归会话当前的后端会话。任务账本只记转接代次，不逐条记「归谁」；每条任务的状态只采信持有者自己报的（research/round15/decisions.md D13）。
- Claude 当前：钩子 mod 截下模型（含它的子代理）对转接任务的 TaskStop、SendMessage、CronList、CronDelete，守护进程转给持有者的动作 mod 执行；读输出用 Read 读原输出文件；Workflow 续跑也截下，但插件调不了 Workflow，按下面的移入走。Codex 当前：每条由 New Desktop 建的根线程在创建时声明 `nd_tasks`（list、read、stop、send）。守护进程只办当前承载位、当前转接代次的请求；启动扫描的裁决例外，任何承载位都答（research/round15/decisions.md D7）。
- 结果的投法：Claude 当前时等回合结束，经动作 mod 以 `asUser` 提交「原生空闲通知的包装＋原文」，模型看到的和原生通知逐字相同；Codex 当前时用 `turn/start.toolOutput`，线程历史里它后面出现模型产出才算投完。
- 转接表只装在当前 Claude 进程里，落定之前装好；会让模型第一次知道某个 id 的投递，等含这个 id 的表确认装好才投。落定之后先投一份转接清单（有内容才投），再解除退役、放出代持（research/round15/decisions.md D1、D3）。
- 已结束的子代理在记录所在的后端会话里就地续接，或在当前后端能原生续接时只把它自己的记录复制进来；Workflow run 续跑时整个移进当前 Claude 后端会话。同一个子代理、同一个 run 任何时刻只有一个写入者（ADR 0008、0011）。
- 定时事项不搬：留在原持有者里照原生到点，到点的提示由持有者的钩子 mod 截下、转投给当前对话。有定时事项的旧进程因此一直退役着，重复的 cron 最长到 CLI 的七天自动过期；任务面板列出它们和删除按钮。
- 持有者是 Claude 进程时，界面的停止按钮是用户停止（`stop_task`），被停的子代理之后谁都续接不了；模型的停止是 stopped by Claude，之后能用原 id 续接。和 CLI 一致。Codex 子代理和守护进程拉起的 Claude 子代理没有这种区分：停只停当前回合，不因此变得不能续接（research/round13/DESIGN.md §3）。
- 持有者意外退出：它起的命令要等看守单元清掉 cgroup 才停，所以停止证据先记「未确认」、单元清理后记「已确认」；给模型的失败通知每个任务只发一次。名下有定时事项的，以退役状态同 id 拉起；CLI 原生恢复出的集合不可信（删过的会复活，ScheduleWakeup 不恢复），核对完之前它到点的提示不转投，按账本把删过的再删掉，恢复不了的在失败通知里列出（research/round13/v2/review-2.md H3）。
- 分叉出的新会话不接原会话的任务（ADR 0008）。
- 做不到的：在跑的 Claude 任务进不了新进程的原生任务表；Codex v2 子代理不收外部消息；用户停下的 Claude 原生子代理不能续接；转投给 Claude 的结果不在回合中途并入；后台 MCP 调用只停 CLI 这边的等待。
- 端口、引擎里的落点见 research/round12/DESIGN.md §2.7，和第 13 轮第三版对齐后的改动见 research/round15/decisions.md。

## Considered Options

- 用 CLI 的 adopt 交接（交接单）：stream-json 进程从不认领交接单；改用 TUI 认领，子代理被中止后要重做被打断的回合，Workflow 在途的 agent 重跑，后台命令丢退出码（research/round13/TEST.md §2、§3、§8）。只在接管 CLI 后台会话时处理它留下的交接单。
- 原地 `rewind_conversation`、不起新进程：声明 `perTaskStopAffordance` 时它停掉被切掉那段里起的任务；不声明，Esc 的 `interrupt` 又会停全部后台任务。它只能退到当前链上的消息，切回、换后端仍要起新进程，转接省不掉；段和后端会话也不再一一对应。
- 把在跑任务搬到新进程（停下再续接、复制运行目录续跑、在新进程重建定时事项）：子代理和 Workflow 搬就要中止重做；重建的定时事项换 id、从重建时重算有效期、丢 /loop 状态，先建后删的窗口里两边都会到点又认不出是哪一次。
- 新模型只看转投文字（ADR 0008 原来的写法）：达不到「当自己的来用」，owner 的要求正是针对它。
