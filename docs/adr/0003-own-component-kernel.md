# 照 Cordis 论文自写组件内核，不复用 Cordis 或 DeepSeek Harness

借的是 DeepSeek Harness「万物皆插件」的思路，也就是 Cordis（论文 arXiv 2608.25512：可撤销副作用加响应式依赖）；但 DeepSeek Harness 的生态在不用它的界面、后端换成 Claude Code 时基本用不上，Cordis 本身是 Node 库（多一个运行时进程，rc.10 还有卸载残留和清理顺序问题），调研见 research/dsh/。所以用 Rust 按论文的机制自写：登记返回守卫句柄、卸下即撤销；按类型登记的提供者表做响应式依赖；配置变化只重建受影响的组件；需要异步收尾的按依赖逆序两段式停止。组件编进程序、按配置启停。

## Consequences

- 守卫只撤销登记和调用权，不结束后端进程，也不释放后端会话的租约。
- 组件停止的原因分两种：交还连接（换代、重载）和结束（真的不要了）。
- 稳定的收件地址不算响应式依赖：适配器把事件交给收件地址，换代时不跟着重建。能原位更新的配置不换提供者。
- 会话组件、后端端口与两个适配器（mod 通道在 Claude 适配里）、看守托管、独占登记不随开关卸下；活着的后端进程需要的处理者，留到它退出为止。
- 界面一侧的撤销在当前帧结束前生效（research/round10/COMPONENTS.md §7.1）。
