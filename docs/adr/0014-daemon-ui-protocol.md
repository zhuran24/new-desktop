# 守护进程与界面之间的协议：快照加事件流，事实落库

界面（桌面，将来的其他电脑和手机）连上守护进程时先取快照，再接事件流。重建不出来的事实落库，事件流只在内存里；守护进程重启后，界面重新取快照。命令带收据和前置条件，并发冲突靠前置条件判；同一个审批几个界面同时答，先答的生效。协议按命名空间分（会话、对话、任务、审批……），每个条目都带后备文字，手机只实现几个命名空间也能用。v1 只开本机 socket；远程只走 Tailscale 加设备配对，权限分两档，v1.1 再做（research/round10/COMPONENTS.md §8）。

## Consequences

- 界面可以整套换掉（owner 2026-10-06）：nd-wire 是界面和守护进程之间唯一的接口，桌面界面不另开私有通道。协议类型只在 Rust 里定义一次，导出 JSON Schema 随仓库公开。任何讲 nd-wire 的程序都能当界面；同步副本、视图模型、输入框状态机不依赖 GPUI，可以直接复用。例外是 MCP App 卡片：它在界面进程里借 Chrome 渲染（ADR 0012），换了界面要自己实现，或者只显示后备文字。Mermaid 由守护进程出 SVG，各个界面共用。
- 外观经主题换：桌面界面的视图只从主题变量取配色、字体、字号、间距、圆角，主题是文件，运行时加载、热切换。

## Considered Options

- 事件流也落盘：守护进程重启后补发更快，但多一套存储。等手机取快照明显变慢时再加。
- 界面做成在桌面程序进程里动态加载的插件（动态库、WASM）：和 ADR 0003「组件编进程序」冲突，Rust 没有稳定的二进制接口，插件一崩还会把整个界面带倒。按进程边界换整套界面，按主题文件换外观，就够用了。
