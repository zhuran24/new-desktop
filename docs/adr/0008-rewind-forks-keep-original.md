# 回退在原会话里进行，后台任务全部保留；分叉才另开会话

官方桌面端回退时会关掉旧会话的 CLI 再开新会话，后台任务全部中断（research/round2/fork.md）。New Desktop 把回退和分叉分开：
- 回退：在当前会话里进行，界面上不新开会话。被切掉的部分进回退记录，可以展开成拓扑图；记录里的任何一段都能切回来，在同一个会话里接着聊。所有已经在跑的后台任务，包括被切掉那段里启动的，都照常跑完，并转接给当前对话：新后端会话的模型用原 id 停止、发消息、读输出、删定时事项，结果以当前后端的通知格式进来（ADR 0016）。这和终端 CLI 自己的 `/rewind` 效果一致。
- 分叉：才在侧栏里多出一个会话，原会话保留。分叉出的新会话不接原会话的任务。

做法照官方桌面端的回退命令：`--resume <旧后端会话> --fork-session --resume-session-at <锚点>` 起一个新后端会话。不同的是旧后端进程不关，而是先让它退役：New Desktop 的钩子 mod 截下它收到的任务通知等投递，转给守护进程，它的主对话不再请求模型。旧进程确认退役后再起新的；它手上的任务跑完、定时事项都结束之后，再把它收掉。

回退记录里每一段由一个或先后几个后端会话承载。切回某段，就是接上它当前的后端会话：进程还在就解除退役，已退出就续接（research/round9/BRIDGE.md §2–3）。

## Consequences

- 每次回退都重启一次后端进程（MCP 重连、SessionStart 钩子重跑），和官方桌面端一样；终端 `/resume` 列表里看得到这些分叉。
- 旧进程手上的任务（包括被切掉那段里起的）和定时事项转接给新后端会话：钩子 mod 截下模型对它们的 TaskStop、SendMessage、CronList、CronDelete，由守护进程转给持有者；Read 读原输出文件；结果等回合结束后以原生通知的正文投入。界面的停止仍发 `stop_task`（research/round13/DESIGN.md）。
- 已结束的子代理：记录所在的后端会话有活进程就在那里就地续接；没有进程而当前后端能原生续接这种记录，第一次续接前只复制它自己的记录到当前后端会话；否则在记录所在拉起、退役后就地续接。已结束的 Workflow run 续跑时整个移进当前 Claude 后端会话。同一会话里，同一个子代理、同一个 run 任何时刻只有一个写入者。同一会话里 Codex 子代理续接同一条线程。会话分叉时才在分叉那一刻复制已结束子代理的记录，来源可以还活着，正在跑的不复制；Codex 子代理在新会话里第一次续接时 `thread/fork` 出自己的线程。这些复制、移动都是 ADR 0011 列的写 CLI 存储的例外，只限那里列的已验证记录种类（research/round15/decisions.md D8、D9）。
- 起分叉进程，以及续接分叉来的后端会话时，设 `CLAUDE_CODE_RESUME_SOURCE_ALIVE=<本后端会话 id>|<扫描边界>`，压住 CLI 对共享前缀里那些任务的孤儿误报；扫描边界是起分叉进程之前那一刻的 UTC 时间，这个后端会话之后每次续接沿用同一个值；会话分叉第一次起进程时加第三段（来源 id），保留原生的 `<fork-source>` 提示，第三段永不写本后端会话 id。扫描边界之后的扫描通知由钩子 mod 按守护进程的账本逐 id 裁决（research/round13/DESIGN.md §2.7）。
- 恢复代码：分叉前对旧进程发 `rewind_files`。同一工作目录里还有别的会话在跑，或本会话（包括退役进程）的子代理、Workflow 还在跑时，不恢复代码，只恢复对话。
- 能选的回退点只限最近一次压缩之后的提示，和 CLI 的回退菜单一致。
- 后端进程声明 `perTaskStopAffordance`，Esc 用官方的 `interrupt`（真模型实测：3–7 ms 结束回合，后台任务不受影响，research/round4/TEST-realmodel.md）；不用 `rewind_conversation`。
- 退役依赖 New Desktop 的 mod 正常装载。等不到 mod 的回应时降级：照官方桌面端停掉旧进程，并事先告诉用户后台任务会被停。
- Codex 会话不做原地回退，只能分叉，和 Codex 桌面端一致；app-server 的 `thread/revert` 会重建会话运行时，后台任务保不住。
- 拉起后端进程的就绪判据不等 `system/init`（它要等第一条用户消息才来），以两个 mod 的 hello 和 initialize 的回应为准。
- 退役进程的收尾判据：钩子 mod 挂的 `Stop`、`SubagentStop` 钩子带来的在途任务表和定时事项都空了，也没有未答复的代管请求。定时事项不迁，留在原进程里到点，有定时事项的旧进程就一直退役着。转投按后端给的稳定投递键去重：Claude 是（后端进程编号，报告 id），stdout 补转按（后端进程编号，任务 id，完成代次）关联；Codex 是（后端会话，子线程 id，子回合 id）或（后端会话，所属线程 id，itemId）。
- 恢复代码要先拿到工作目录的占用，执行时重新检查条件。

## Considered Options

- mod 压缩钩子原地删段，切段靠回放加压缩（本 ADR 的上一版）：回放期间任务通知会触发推理，目标段的附件会丢，整段记录换新 uuid，钩子出错时会退回真的压缩；回放的那段还要重写提示缓存。
- 回退就是分叉，原会话带着任务继续跑（更早一版）：任务结果只回到没人再用的旧会话，owner 认为没用。
- 原地 `rewind_conversation`、不起新进程：声明了 `perTaskStopAffordance` 它就停掉被切掉那段里起的任务；不声明，Esc 的 `interrupt` 又会停全部后台任务。它也只能退到当前链上的消息，切回、换后端仍要起新进程，转接省不掉（ADR 0016）。
